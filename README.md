# מסלול החפיפה

אתר לניהול חפיפה: לכל נחפף יש פורטנייטים עם זמן מוקצב, רשימת שאלות, לוח ימים שבהם הוא לא במאמן ופינת פתקים. החופף האישי רואה ועורך את העמודים של הנחפפים שלו, והחופף הראשי מנהל את כולם ומקבל דוחות.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האתר כולו (עיצוב + לוגיקה) |
| `firebase-config.js` | חיבור ל-Firebase: סנכרון בין המחשבים וסיסמאות (ראו למטה) |
| `firestore.rules` | כללי האבטחה שמדביקים ב-Firebase |
| `serve.ps1` | שרת קטן לבדיקה ברשת המקומית |

- **המסר היומי:** פינה שבה הנחפף והחופף משאירים זה לזה מסר קצר, עם צבע ואימוג׳ים. כששלחתם מסר היום, מופיע "נשלח היום ✓".
- **דיווחים והערות:** מקום חופשי שבו הנחפף כותב כל דבר על החפיפה. אפשר גם לדווח על שאלה מסוימת מהצ׳קליסט (⚑). כשהחופף לוחץ "טופל", הדיווח יורד מהרשימה.
- **לשון פנייה:** בעמוד **משתמשים** בוחרים לכל משתמש זכר או נקבה, והטקסטים באתר מותאמים (למשל "עובדת על זה", "נחפפת"). בלי בחירה, הטקסט נשאר בצורה "עובד/ת".

העמוד של הנחפף מתמקד בהתקדמות: הפורטנייט הנוכחי וכמה שאלות בוצעו בו, מה הלאה, ומה כבר הושלם. אין אצלו ספירה לאחור או סימוני איחור. אצל החופף האישי אותו נחפף מוצג עם הדדליין, הזמן שנשאר, הארכות ואיחורים.

## איך מתחילים

1. בפעם הראשונה שפותחים את האתר נוצר **החופף הראשי**: שם וסיסמה.
2. בעמוד **תכנית החפיפה** מוסיפים את החלקים של החפיפה: שם, כמה ימים מוקצבים ואילו שאלות יש בכל חלק.
3. בעמוד **משתמשים** יוצרים חופפים אישיים ונחפפים לפי שם. לכל נחפף בוחרים חופף אישי, ואפשר להעתיק אליו את תכנית החפיפה.
4. כל משתמש נכנס, בוחר את השם שלו, ובכניסה הראשונה בוחר לעצמו סיסמה (עם Firebase, גם מקליד את הקוד שקיבל). מי ששכח סיסמה, החופף הראשי מאפס לו אותה (🔄) והוא בוחר חדשה.

## הצ׳קליסט

החופף הראשי מגדיר בעמוד **תכנית החפיפה** את השאלות של כל חלק. כשנחפף מתחיל פורטנייט, השאלות של החלק הזה מועתקות לצ׳קליסט שלו, והוא מסמן ✓ או "עובד/ת על זה". כשהוא מסמן שסיים את החלק, השאלות יוצאות מהצ׳קליסט. החופף האישי והחופף הראשי רואים גם את השאלות של שאר החלקים ויכולים להכין אותן מראש.

## מצב הדגמה

כדי לראות איך האתר נראה לכל תפקיד עם נתונים לדוגמה, מוסיפים לכתובת `?demo=admin`, `?demo=mentor` או `?demo=trainee`. במצב הזה שום דבר לא נשמר ולא נשלח ל-Firebase, ומרעננים כדי להתחיל מחדש.

## איך הזמן נספר

- ראשון עד רביעי: יום אחד. חמישי: חצי יום. שישי ושבת: לא נספרים.
- ימים שהנחפף סימן שהוא לא במאמן, וחגים שהחופף הראשי סימן בעמוד **חגים**, לא נספרים. חצי יום שסומן מוריד חצי יום.
- סימון יום: לחיצה אחת = לא במאמן כל היום, לחיצה שנייה = רק חצי יום, לחיצה שלישית = ביטול. בחמישי (שממילא חצי יום) אין שלב של חצי.
- יום ההתחלה נספר. הדדליין הוא היום שבו מצטברים כל הימים המוקצבים (כולל הארכות).
- כשמסמנים יום חופש או מוסיפים הארכה, הדדליין מתעדכן מיד.
- פורטנייט שהסתיים: "ימים בפועל" הם ימי העבודה מיום ההתחלה ועד יום הסיום. אם יצא יותר מהמוקצב, הוא מסומן "באיחור".

## העלאה לאוויר עם Firebase וסיסמאות אמיתיות, שלב אחר שלב

בסוף התהליך האתר יושב ב-GitHub Pages. Firebase שומר את כל הנתונים ומסנכרן אותם בין המחשבים, ו-Firebase Authentication מנהל את הסיסמאות. האתר עצמו לא רואה ולא שומר אף סיסמה. הכל בתכנית החינמית.

### שלב 1: פרויקט Firebase

אפשר להשתמש בפרויקט של המקרר (`mekarer-d4b40`). אז מדלגים לשלב 1.3 ומעתיקים את אותו `firebaseConfig` מ-`firebase-config.js` של המקרר. הנתונים של החפיפה נשמרים באוספים נפרדים שמתחילים ב-`hafifa_`.

1. נכנסים ל-https://console.firebase.google.com עם חשבון Google ולוחצים **Create a project**. Google Analytics לא נחוץ.
2. במסך הפרויקט לוחצים על האייקון **`</>`** (Web), נותנים כינוי, **לא** מסמנים Firebase Hosting, ולוחצים **Register app**.
3. מעתיקים את הקטע `const firebaseConfig = { ... };` ומדביקים אותו בקובץ `firebase-config.js`, במקום שמסומן שם, ושומרים. (הקטע נמצא תמיד גם ב-Project settings ← Your apps ← Config.)

### שלב 2: הפעלת סיסמאות (Authentication)

1. בתפריט הצד: **Build ← Authentication ← Get started**.
2. בלשונית **Sign-in method** בוחרים **Email/Password**, מדליקים את המתג הראשון (Email/Password, לא Email link) ולוחצים **Save**.

זה הכל. המשתמשים לא צריכים כתובת מייל: האתר יוצר לכל אחד כתובת פנימית בסגנון `k3x9ab.0@example.com`, שהוא לא רואה. היא לעולם לא מקבלת מייל, כי `example.com` היא כתובת שמורה שלא שייכת לאף אחד.

### שלב 3: מסד הנתונים וכללי האבטחה

1. **Build ← Firestore Database ← Create database** (אם עוד אין). בוחרים מיקום קרוב כמו `europe-west1` ו-**Start in production mode**.
2. בלשונית **Rules** מוחקים את כל מה שיש, מדביקים את **כל** התוכן של הקובץ `firestore.rules` מהתיקייה הזו, ולוחצים **Publish**.
   אם בכל זאת משתמשים בפרויקט של המקרר, מוסיפים בתחילת הכללים, מתחת לשורה `match /databases/{database}/documents {`, את הבלוק `match /items/{id} { allow read, write: if true; }` כדי שהמקרר ימשיך לעבוד.

הכללים קובעים מה כל אחד יכול לקרוא ולכתוב:
- לפני כניסה רואים רק את רשימת השמות.
- נחפף רואה ועורך רק את הדברים שלו.
- חופף אישי רואה ועורך את הנחפפים שלו.
- רק החופף הראשי יוצר משתמשים, קבוצות, חגים ותכנית חפיפה.

### שלב 4: העלאה ל-GitHub Pages

1. נכנסים ל-https://github.com (פותחים חשבון אם אין) ולוחצים **New repository**. נותנים שם, למשל `hafifa`, בוחרים **Public**, ולוחצים **Create repository**.
2. במסך של המאגר החדש לוחצים **uploading an existing file**. גוררים לשם את הקבצים `index.html`, `firebase-config.js`, `firestore.rules` ו-`README.md`, ולוחצים **Commit changes**.
3. **Settings ← Pages**. תחת Branch בוחרים `main` ו-`/ (root)`, ולוחצים **Save**.
4. אחרי דקה או שתיים מופיעה בראש העמוד הכתובת `https://<שם המשתמש>.github.io/hafifa/`.

כשמשנים קובץ בהמשך: נכנסים לקובץ במאגר, לוחצים על העיפרון (או מעלים אותו שוב ב-**Add file ← Upload files**) ולוחצים **Commit changes**. האתר מתעדכן תוך דקה.

המפתחות בקובץ `firebase-config.js` אינם סוד. הם נועדו להיות גלויים באתר, ומה ששומר על הנתונים הם כללי האבטחה משלב 3.

### שלב 5: החופף הראשי נכנס ראשון

**חשוב: עושים את זה מיד אחרי ההעלאה.** מי שפותח את האתר ראשון הוא זה שנהיה החופף הראשי.

1. פותחים את הכתובת. בפינת הכותרת צריך להופיע התג הירוק **"מסונכרן"**.
2. במסך הפתיחה כותבים שם ובוחרים סיסמה (לפחות 6 תווים).

### שלב 6: הוספת כל השאר

1. בעמוד **משתמשים** יוצרים חופפים אישיים ונחפפים. לכל משתמש חדש מופיע בטבלה **קוד כניסה ראשונה** בן 6 ספרות.
2. שולחים לכל אחד את כתובת האתר ואת הקוד שלו.
3. בכניסה הראשונה הוא בוחר את השם שלו, מקליד את הקוד ובוחר סיסמה. מכאן והלאה הוא נכנס עם השם והסיסמה בלבד.

- **שכחו סיסמה:** החופף הראשי לוחץ 🔄 ליד השם בעמוד **משתמשים**. מופיע קוד חדש, והמשתמש נכנס איתו ובוחר סיסמה חדשה. הסיסמה הישנה מפסיקה לעבוד מיד.
- **החלפת סיסמה:** כל משתמש מחובר יכול להחליף את הסיסמה שלו בכפתור 🔑 שבכותרת.

### אם משהו לא עובד

| מה רואים | מה עושים |
|---|---|
| "Firebase חסם את הגישה" | הכללים לא הודבקו נכון. חוזרים לשלב 3.2 ומדביקים את כל הקובץ `firestore.rules` |
| "צריך להפעיל ב-Firebase את Authentication" | חוזרים לשלב 2 |
| "הקוד לא נכון" | בודקים את הקוד בעמוד **משתמשים**. אם הסיסמה אופסה, יש קוד חדש |
| התג בכותרת כתום או אדום | אין חיבור לאינטרנט, או ש-`firebase-config.js` לא הועלה עם ההגדרות |

### מה עדיין כדאי לדעת

- הנתונים שנשמרו עד עכשיו בדפדפן, בלי Firebase, לא עוברים אוטומטית. מתחילים את האתר המחובר מההתחלה.
- כל מי שיש לו את כתובת האתר רואה את רשימת השמות במסך הכניסה, אבל לא שום דבר מעבר לזה.
- נחפף יכול לערוך רק את הנתונים שלו. מי שמבין בקוד יכול לעקוף את הכפתורים באתר ולשנות לעצמו פרטים, למשל ימים מוקצבים, אבל לא לגעת בנתונים של מישהו אחר.

## בדיקה ברשת המקומית (לא חובה)
```bash
powershell -ExecutionPolicy Bypass -File .\serve.ps1
```
הסקריפט מדפיס כתובת כמו `http://192.168.1.20:8080/` שאפשר לפתוח ממחשבים אחרים באותה רשת, כל עוד המחשב הזה דלוק.

## דוחות

בעמוד **דוחות**:
- מספרים מרכזיים: כמה בחפיפה, כמה פורטנייטים פעילים, כמה באיחור, כמה שאלות שצריך בהן עזרה.
- **מה דורש תשומת לב**: מי באיחור ובאיזה פורטנייט, מי ביקש עזרה, למי היום הוא היום האחרון, ומי לא באמצע פורטנייט.
- **הארכות אחרונות** עם הסיבה שנכתבה.
- **איפה כל אחד נמצא**: השלב הנוכחי, הזמן שנשאר, חלקים, שאלות והארכות.
- **כמה זמן לקח כל חלק**: טבלה של ימים בפועל מתוך המוקצב לכל נחפף ולכל חלק, עם ממוצע. כפתור **הורדה לאקסל** מוריד את הכל כקובץ CSV.
